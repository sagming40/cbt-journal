# 0008. 폼 라이브러리를 쓰지 않는다

- 상태: 채택 ([0003](0003-frontend-sveltekit-spa.md)의 "폼은 `sveltekit-superforms` + Zod"만 대체. 나머지 0003은 그대로)
- 날짜: 2026-11-02

## 맥락
- 0003에서 폼을 `sveltekit-superforms` + Zod로 정했지만, M2 · M4는 넣지 않고 만들었다. M2 때 "M5에서 다시 본다"고 미뤘다(DEVLOG).
- M5의 S-04는 8단계 + 자동 저장(입력이 멈추면 저장, 저장 요청은 한 번에 하나, `rev` 충돌)이다. "제출 한 번 → 검증 → 결과"라는 superforms의 흐름과 다르다.
- 이 앱은 SPA라 SvelteKit의 form action을 쓰지 않는다. 검증의 원본은 서버이고(`INVALID_INPUT` + `fields`), 화면은 받은 문구를 칸 아래에 보여 주기만 한다.

## 결정
- 폼 라이브러리를 넣지 않는다. Svelte 상태(`$state`) + 서버 검증 + `FormError`로 간다.
- 화면에서 미리 보는 것은 "버튼을 켤지"(필수 칸이 찼는지) 정도만 작은 함수로 둔다. 규칙의 원본은 서버다.

## 검토한 대안
| 후보 | 탈락 이유 |
|---|---|
| superforms + Zod | SPA 모드로 쓸 수는 있지만 자동 저장 흐름과 맞지 않고, 서버 규칙을 Zod로 한 벌 더 옮겨 적게 된다 |
| Zod만 | 서버가 이미 칸별 문구를 준다. 화면에서 같은 규칙을 또 적으면 어긋날 곳만 늘어난다 |

## 감수할 것
- 긴 입력 폼이 많아지면 칸별 오류 연결(`aria-describedby` 등)을 손으로 반복한다. 그때 작은 부품으로 뽑는다.
