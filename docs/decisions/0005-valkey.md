# 0005. Valkey를 붙이고 PostgreSQL과 역할을 나눈다

- 상태: 채택
- 날짜: 2026-10-29

## 맥락
- 처음 검토에서는 Redis 계열을 붙일 이유가 약했다. 세션은 DB로 충분하고, 통계 캐시는 기록 몇백 건 집계라 필요 없고, 작업 큐도 없었다.
- 사용자는 "메인 DB + Redis" 구조를 배우고 싶어 했다. 그래서 억지로 끼우는 대신, **Redis 계열이 실제로 필요한 기능을 갖춘 앱**으로 방향을 잡았다([0001](0001-rewrite-v2.md)의 "연습 도구" 방향).
- Redis는 2024년 라이선스를 바꿨고(현재 AGPL 포함 삼중 라이선스), 그 뒤 Linux 재단이 BSD 라이선스 포크 **Valkey**를 만들었다. 프로토콜이 호환돼 같은 클라이언트를 쓴다.

## 결정
**Valkey**를 쓴다. Go 클라이언트는 `go-redis`, 작업 큐는 `asynq`.

**역할 분담 원칙 (어기지 말 것)**
- **PostgreSQL = 진실의 원천.** 영구히 남아야 하는 데이터는 전부 여기.
- **Valkey = 휘발성 · 파생 데이터와 작업 조율.** Valkey가 통째로 날아가도 잃는 건 작성 중 초안 정도여야 한다.

| 용도 | 내용 |
|---|---|
| 세션 캐시 | 세션 원본은 Postgres, 조회 캐시는 Valkey |
| 요청 제한 | 로그인 시도 · 가입 남용 방지 |
| 통계 캐시 | 대시보드 집계 결과. 기록이 저장 · 수정 · 삭제되면 무효화 |
| 초안 자동저장 | 작성 중인 사고 기록을 몇 초마다 저장, TTL로 자동 정리 |
| 작업 큐 | 리마인더 웹 푸시, 주간 리포트 생성 (`asynq`) |

세션 저장소 · 요청 제한기는 Go 인터페이스로 감싸서 구현체를 바꿔 끼울 수 있게 한다.

## 검토한 대안
- **붙이지 않기**: 지금 규모만 보면 충분하다. 배우려는 목적과 위 기능들 때문에 붙였다.
- **Redis 원조**: 자료가 가장 많고 개인 프로젝트엔 라이선스 문제도 없다. 라이선스가 단순한 Valkey를 골랐다.

## 감수할 것
- 운영할 프로세스가 하나 늘고(api · worker · Postgres · Valkey), 캐시 무효화 버그가 생길 자리가 생긴다.
- 개념 설명(Valkey가 뭔지, Redis와 관계)은 Valkey를 처음 붙이는 단계에서 한다 — PLAN에 적어 둔다.
