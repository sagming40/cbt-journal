# 0001. v1을 버리고 전면 재작성한다

- 상태: 채택
- 날짜: 2026-10-29

## 맥락
- v1(2026-07, Express + React + PostgreSQL)은 포트폴리오용으로 시작해 Phase 3 언저리에서 멈췄다. 일기 작성 화면·대시보드·삭제가 없고, 검증·에러 처리·테스트가 거의 없다.
- 취업으로 포트폴리오 목적이 사라졌다. 이제 기준은 **직접 쓰고 싶은 앱을 취미로 제대로 만드는 것**이다.
- v1을 읽어 보니 고쳐 쓰기보다 다시 짓는 편이 싸다: 응답 형식이 제각각이고, 컨트롤러에 SQL이 섞여 있고, 프론트는 Vite 템플릿 잔재 위에 화면 3개뿐이다.

## 결정
1. v1 코드는 git 태그 `v1-legacy`로 남기고 **새 스택으로 처음부터 다시 만든다.** v1 문서는 `docs/archive/`에 보관만 한다.
2. 방향을 **"가끔 길게 쓰는 일기장" → "매일 짧게 들어와 연습하는 CBT 도구"**로 바꾼다. 빠른 감정 체크인, 7칸 사고 기록지(근거 · 반대 근거 추가), 리마인더, 주간 리포트가 핵심이다.
3. **구조는 다중 사용자, 운영은 혼자 쓰기로 시작한다.** 모든 사용자 데이터에 소유자를 두고 조회를 소유자 범위로 강제한다. 회원가입은 설정 플래그로 막아 두고, 공개할 때 연다.
4. 같은 이유로 7월 로컬 DB 데이터는 옮기지 않는다(테스트 데이터뿐). 필요한 예시 데이터는 seed로 다시 만든다.

## 검토한 대안
- **v1을 이어서 완성**: 스택이 익숙해 빠르지만, 위의 구조 문제를 전부 고쳐야 하고 새로 배우는 재미가 없다.
- **처음부터 혼자 쓰는 앱으로 설계**: 가장 가볍지만, 나중에 공개하려면 모든 테이블·쿼리에 소유자를 끼워 넣어야 한다. 뒤늦게 넣는 비용이 지금 넣는 비용보다 훨씬 크다.

## 감수할 것
- 지금까지 만든 화면·API를 하나도 재사용하지 않는다.
- 혼자 쓰는 동안에도 인증·소유자 검사 코드를 갖춰야 한다.
