# mockups — 화면 목업

> **화면 그림을 어떻게 보고, 어느 파일이 무엇이고, 무엇을 채택했는지** 적는 문서다. 그림은 [DESIGN.md](../DESIGN.md)의 결정을 보여 주는 참고 자료이고, 규격 · 색의 단일 출처는 DESIGN이다.
> **로컬 파일로만 둔다.** claude.ai 캔버스 · Artifact에 올리지 않는다(CLAUDE.md 업로드 금지 규칙).

## 보는 방법
- `shared.js` · `shared.css`를 같은 폴더에서 불러오므로 **로컬 웹 서버로** 연다. 더블클릭(`file://`)으로 열면 브라우저에 따라 공용 파일을 못 불러온다.
  - 예: 이 폴더에서 `python -m http.server 5199` (conda 환경이 켜진 터미널) 또는 `npx http-server -p 5199` (http-server를 npm 캐시에 임시로 받는다. 프로젝트에는 아무것도 안 생긴다)
- 화면 위 도구 막대로 **시안(A ~ D) · 다크**를 바꿔 본다. 주소에도 남는다: `Checkin.mobile.html?palette=B&dark=1`
- 칩 · 슬라이더 · 단계 전환은 실제로 눌러 볼 수 있다.

## 언제 · 왜 그렸나
**나머지 화면은 그 화면을 구현하는 단계에서 필요할 때만 그린다** — 색 · 스타일 · 핵심 화면이 정해지면 나머지는 같은 부품의 조합이라, 미리 그리면 구현 때 다시 고치게 된다.

| 보드 | 언제 | 왜 |
|---|---|---|
| 컬러 시안 | 2026-10-29 (M0) | DESIGN 6장 토큰을 정해야 뼈대 단계(M1)에서 테마를 깐다 |
| 스타일 시안 · 로고 시안 | 2026-11-01 (M4 전) | 기본 shadcn 모양이 밋밋하다(사용자 의견). 화면을 만들기 전에 결을 정해야 부품을 다시 안 만든다 |
| S-03 체크인 · 모바일 | M0 | 10초 목표(REQUIREMENTS C1)가 이 배치로 되는지 눈으로 확인 |
| S-04 사고 기록 · 모바일 / 데스크톱 | M0 (옛 결 — M5 구현이 기준) | 붙잡기 단계(1 ~ 3) · 정리 단계(4 ~ 8)를 어떻게 나누고 넓은 화면을 어떻게 쓰는지 |
| PC 화면 D2 | 2026-11-01 | PC 화면이 본문 한 줄이라 넓은 화면이 비어 보였다(사용자 의견) |
| S-05 · S-07 (M6) | 그 화면을 구현할 때 | `Desktop.html`의 S-05 · S-07을 출발점으로, 필요하면 모바일만 더 그린다 |

넷 다 글자 대비 4.5:1(WCAG AA)을 넘는다. 확정 토큰은 DESIGN 6장. 목업은 주소에 `palette`가 없으면 B로 그린다.
입력칸 · 버튼 테두리는 장식 테두리(`border`, 1.3:1)가 아니라 `input`(3:1 이상)을 쓴다.

## 스타일 시안 (2026-11-01 **D2 채택** — 확정 값은 DESIGN 6장)
지금 목업 · 앱이 shadcn 기본 모양 그대로라 밋밋해서(사용자 의견), 다른 프로젝트 목업(PlayLedger · 자재 사전 — 어두운 바탕 · 큰 굵은 제목 · 벤토 카드 · 알약 메뉴)을 참고해 방향 셋을 그렸다. 색 규칙(6장 — 남색 하나, 빨강 · 주황 · 초록 없음, 강도는 명도)은 셋 다 그대로 지킨다. `Style.html`은 혼자 서는 파일이라 `shared.js`를 안 쓴다(B는 명조 글꼴 고운바탕을 Google Fonts에서 불러온다 — 목업만).
